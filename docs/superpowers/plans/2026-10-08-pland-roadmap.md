# PlanD：開発全体計画

2026-10-24更新。既存のAndroid・実験PWA・公開デモを引き継ぎ、**端末内で使える機能を先に完成させ、端末間の通信を後半で統合・検証する。**

本書は開発順序と完成条件を示す。確定した動作は[設計書](2026-10-19-integrated-design.md)、現在の実装と試験結果は[実装・試験状況](../../STATUS.md)、未確定の追加案は[検討資料](2026-10-22-research-and-feature-options.md)を参照する。`plan.txt`と`add.txt`は利用者が管理する原文として保持する。

## 1. 最終目標と最初の実証

通信網が途絶えた災害現場で、確認・救助が必要な人と場所、その理由を把握し、担当を決め、対応結果を共有する。建物情報と巡回ルートで活動を助け、近距離通信・音響・その他センサーによる埋没者の居場所特定まで目指す。

最初の利用者は町内会・自主防災組織。最初の実証版では、**地震の成立→安否回答→地図・一覧で対象を発見→担当・対応→結果共有**を一巡させる。担当者は活動名で表示し、メンバー自身の対応開始と班長・管理者による調整を扱う。

## 2. 現在の成果を使う

| 既存の成果 | 今後の扱い |
|---|---|
| 住民・住居・寝室、建物・住戸、個人・建物への対応と訂正、端末内保存 | 既存の記録を保持して拡張。保存形式の変更には移行試験を付ける |
| Android 1.5.3の地図・安否、詳細・凡例・動的集約、描画の改善 | 採用済みの表示を使い、実測位と保存データへ接続する |
| 公開Webデモの全体一覧・安否別一覧・エリア一覧 | Androidへ移植し、実データで操作できるようにする |
| Nearby、実験WSS、保存後の受領確認、再送・中継、接続後の背景共有 | 既存処理を維持し、第6段階で新しい記録を接続する |
| 実験PWA、Windows相手役、過去の試験 | 第6段階の相互運用試験に再利用する |

開発先は`android/`。Kotlin・Compose・Room・MapLibre・Nearbyと最小SDK24を継続する。公開デモと試験用の架空データは、通常の保存情報と区別して使う。

## 3. 進め方

**現在の指示：画面デザインの変更を伴わない処理は、下表の工程順にかかわらず実装する。** 保存・権限・集計・同期の独立した実装と自動試験を先に進める。下表の段階全体の終了条件は維持し、保存APIだけを作った機能を画面まで完成した扱いにはしない。実機の端末間試験はまとめて行う。

今回の実装単位と結果は[画面変更を伴わない実装の記録](2026-10-24-backend-results.md)に記載する。仕様待ちはその仕様を使う機能だけに限定する。


各機能を「画面で操作→端末内に保存→再起動後に確認」まで完成させる。他人の回答・位置・担当操作は、独立した試験データを使って1台またはPCで再現する。

記録ID、対象者・作成者、災害ID、操作・取得時刻、更新番号、訂正先は、その記録を作る段階で揃える。重複や古い更新の扱いも端末内の自動試験で確認する。後半では、その保存処理へ通信を接続する。

**まとめて行うのは実機を使う端末間の結合試験。** 保存・集計・画面の自動試験、1台での測位・権限・再起動の確認は開発中に行う。通信試験で見つかった問題は修正箇所と関連する経路を再試験する。

### 着手・終了・次工程への共通条件

- **着手：** 下表の前提が揃い、その作業に影響する[確認事項](2026-10-20-decisions.md#工程ごとの仕様確認)が回答済みである。対象、試験入力と期待値、必要な端末・データ、成果物を試験票に記載する。仕様の調査・比較は回答前にも行える。
- **終了：** 各節の必須試験がすべて合格し、対象版・環境・結果・成果物の場所を記録する。不合格と未実施が0件になったら終了とする。実装済みでも試験待ちなら未完了。
- **次へ進む：** 下表の条件を満たした工程へ移る。終了済みの工程は追加の見た目調整や最適化で開き直さず、改善は別項目にする。後工程で不具合が見つかった場合は、その修正と影響範囲の再試験を記録する。
- **待ちがある場合：** 待っている仕様・機材と未実施項目を記録する。待ち項目を使わない調査・試験準備・独立した実装は進められる。その際は、使用する保存処理・データ形式の試験が合格していることと、待ち項目への依存がないことを記録する。前工程の終了扱いや、統合試験の省略とは区別する。

## 4. 開発順序

### 第1段階：安否と最後の位置を、1台で使えるようにする

- スマホで実際に位置を取得し、座標・取得時刻・精度・更新番号を保存する。普段の住居・寝室は別に保持する。
- 位置記録中は平常時5分ごと、災害中1分ごとに取得を要求し、位置記録の開始時・地震成立時・安否変更時にも要求する。実際の取得間隔と電池消費を測定する。地震成立との接続は第2段階、消灯中の確認は第5段階で行う。
- 災害ごとの無事／SOSと最大500文字の本人のSOSメモを保存する。既存の救助・訂正を地図と詳細に反映する。
- 採用済みの地図と、全体・安否別・位置不明・エリアの一覧を保存データにつなぐ。
- 保存済みの最後のスマホ位置を取得時刻付きで表示する。未取得は位置不明の一覧へ置き、測位できないときも最後の点を保持する。
- 無事・救助済みの氏名非表示、登録住居とスマホ位置の区別を全画面で揃える。

**終了条件（すべて合格）：** 実測位の取得・保存・再表示、無事／SOSとメモの変更・再起動後の保持、全体／安否別／位置不明／エリア一覧の人数と詳細の一致、救助・訂正と氏名表示の切替、既存記録を保持した保存形式の移行。位置未取得・長期間更新なし・測位失敗の各ケースで期待した表示になることを試験する。

この段階の災害・他の参加者は試験記録で用意する。正式な開始条件は第2段階で接続する。

メモは空欄・500文字・上限超過を試験し、500文字まで保存でき、上限を超える本文が保存されないことを確認する。測位要求は平常時／災害中の間隔と開始・成立・安否変更の各契機を試験入力で確認し、実際の取得間隔・電池消費は測定結果として記録する。

### 第2段階：地震発生から終了までの操作を整える

- PCで作る試験用設定ファイルから、参加者と管理者を読み込む。参加者の招待・承認画面は後続の運用整備で扱う。
- 地震報告、本人の取消、必要人数による成立、管理者の終了を端末内で処理・保存する。
- 必要人数は全メンバー数Nに対して `min(10, max(2, ceil(N / 3)))`。人単位で数える。
- 最初の報告の操作時刻から30分以内を集計し、経過時間も最初の報告から表示する。
- 成立した災害への初回回答を地図の前に求め、回答済みなら再起動後も地図を開ける。終了後は他人の位置閲覧を閉じる。
- 緊急地震速報は試験用の入力で画面・状態遷移を確認する。実配信の接続は後半の通信作業に含める。

**終了条件（すべて合格）：** N=1・2・3・5・7・10・27・28・100の必要人数、同一人物の重複排除、30分の内外、成立前取消、成立後の遅れた取消、管理者終了後の古い成立記録、一般メンバーの終了拒否を試験する。報告→成立→初回回答→閲覧→終了が保存・再起動をまたいで一致し、新しい災害で初回回答を再要求する。未合意の時刻境界の扱いは確認事項を解決してから試験の期待値を確定する。

既存の災害・回答・対応記録は履歴として保持する。これまでの1人開始の記録と、新しい人数成立の根拠を区別する。

### 第3段階：担当と対応結果を記録できるようにする

- SOS／応答なしの対象者に、担当、活動名、未対応／対応中／対応済、対応内容を表示する。
- メンバー自身の対応開始、班長・管理者の担当調整、結果と訂正を保存する。
- 本人の安否、個人への対応、建物の確認範囲を別々に表示する。
- 既存の個人・建物への対応記録を使い、地図・一覧・詳細から状況を確認できるようにする。

**終了条件（すべて合格）：** 自分で対応開始、班長・管理者の担当変更、一般メンバーの権限外操作の拒否、対応結果・訂正の履歴保持、再起動後の復元、一覧と詳細の一致を試験する。個人の救助済みと建物の対応範囲を別々に保存できる。重複引受けと引継ぎは、着手前に合意した操作で解消できることを試験する。

担当の併存、班長・管理者による調整、結果を伴う対応完了は合意済み。操作画面の追加は別作業とする。

### 第4段階：建物と衝撃の情報を加える

- 1地域のPLATEAU等から建物形状・構造・建築年代などを取り込み、端末内で参照できるようにする。
- 建物から登録者の安否・最後の位置・住居・寝室を確認する。
- 評価方法を選定後、根拠付きの建物評価を採用済みの半透明色で表示する。
- Android1台で衝撃を観測し、日時付きで保存・表示する。検知条件は測定して選ぶ。

**終了条件（すべて合格）：**

- 対象1地域の建物形状・取得可能な属性を保存し、オフラインで建物→登録者→住居・寝室・最後の位置を参照できる。
- 建物評価の入力項目・判定方法・版・適用範囲・根拠を文書化し、利用者が採用する方法を確認する。
- 採用方法の各評価区分と属性不足の試験例で期待値が一致し、建物ごとの半透明色・凡例・詳細の評価と根拠が一致する。再起動とオフラインでも表示できる。
- 衝撃の試験入力と1台の実測で、観測日時・検知方法・表示を確認する。合意した検知条件に対して検知あり／なしを検証し、日常動作での誤検知の測定結果を残す。

**建物属性の表示だけでは第4段階は終了しない。** 評価方法の確認待ちでも独立した後続作業は進めるが、本段階は未完了として残す。建物評価の表示・計算の合格と、実際の建物被害に対する推定精度の評価は試験結果を分ける。閉所・埋没者探索は後述の独立した研究工程で扱う。

### 第5段階：1台での利用を仕上げる

- 本人が開始した位置記録を画面消灯中も動かし、停止・再開・権限変更・省電力時の挙動を確認する。
- 保存済み地図と属性のオフライン表示、既存記録の移行、保存失敗からの復旧を確認する。
- API24と新しいAndroid、文字拡大、TalkBack、同じ操作条件での速度・メモリ・電池消費を確認する。
- 地震成立から対応結果までを1台で通し、主要操作の不具合を解消する。

**終了条件（すべて合格）：** 準備済み地図・建物属性を通信なしで再表示できる。位置記録の開始・消灯・画面復帰・停止・再開・権限拒否／取消の各操作で、通知・保存内容・停止後の挙動が一致する。API24と新しいAndroidで主要操作を一巡し、文字拡大とTalkBackで登録・安否変更・対象確認・結果保存を完了できる。同一データ・操作の開始時／終了時のメモリ、処理時間、電池消費を記録し、試験中のクラッシュ・ANR・保存失敗の未解決件数が0件である。

この版の測定は、同じ保存データで地図の拡大縮小24回、一覧・詳細の往復10回、前面放置30分、消灯30分を各1回行い、開始・終了時の画角・件数と測定値を残す。操作不能・誤表示・記録欠落・停止後の処理継続を修正して再試験する。測定済みの追加最適化は別案件にし、この工程の終了を際限なく延ばさない。必須環境で未確認の項目がある間は本段階を未完了とする。

3. 結果の訂正と管理者終了を逆方向にも渡し、再起動・通信断後の再送を確認する。
