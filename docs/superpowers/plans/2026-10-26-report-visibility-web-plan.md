# 通報・安否の公開範囲 Webデモ Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 合意済みの通報アイコン、地域・役割別の個人表示、反応なしの3分待機をWeb案1.6.4で確認できるようにする。

**Architecture:** 旧比較画面を維持し、新版は独立した架空データと閲覧条件を持つ。共通の公開用データ生成を地図・一覧・人物詳細・通報・地域集計の個別表示・CSVで使う。既存フレームにはデータの注入口だけ追加し、新版固有の表示は別モジュールへ置く。

**Tech Stack:** 既存のES modules、MapLibre、Node test runner。

**Spec:** [確認した仕様](2026-10-26-report-visibility-design.md)

## Global Constraints

- 架空データのみ。Android・plan.txtは変更しない。旧版5枚は残して右端へ追加。
- 表示の模擬であり、住所からの所属認証・実データのアクセス制御とは説明しない。
- 実登録の担当区域の決め方は未決定のまま。デモでは既存の架空の東・中央・西町内会を選択して閲覧範囲を試す。エリア管理者は選択町内会、自治体職員は架空市の例。
- 高は提供赤PNG、中・低は提供黄PNG、未設定は旗。SOSの安否記号は維持する。
- デモの時刻は「速報受信」「最初の報告」の架空時刻と経過秒数を選べるようにし、3分の前後・後続の報告で延長されないことを試す。実端末の速報受信には接続しない。

## Review Focus

- 地図や建物・位置不明一覧から、他町内会・自治体に個人詳細が見えない。
- 179999msでは反応なしの氏名・位置・住居・メモが出ず、180000msから地域条件を満たす場合だけ出る。
- 市・区等の集計で件数は維持し、統計だけの対象について個人ID・メモ等をCSVへ含めない。
- 現在位置が分かるSOSに住所・寝室・登録住居への導線を出さず、位置不明の閲覧可能な対象だけに出す。
- デモ内の立場・町内会・経過時間を変えたら、開いた詳細・CSV・地図記号を現在の条件へ更新する。

## ローカル確認結果

- Nodeの全デモ試験26件成功（新規8件＋既存18件）。モデルで179999msと180000msの境界、起点順序と追加報告での非延長、他町内会・自治体への個人情報非表示、通報者の番地／氏名の公開範囲を確認。
- ブラウザーで開始直後は東町内会のSOSのみ氏名表示、反応なしの氏名・個別位置・住居は非表示。3分後に東町内会の反応なし・位置不明が表示され、位置不明の人の登録住所を確認できる。
- 現在位置が分かるSOSの詳細には登録住所・登録住居へのボタンを表示しない。
- 自治体職員の一覧は安否統計だけ。対応一覧は通常の通報4件だけで、通報者の氏名・番地を表示。自治体用の通報CSVを実際にダウンロードし、SOSの個人ID・氏名・メモが入らず、通常通報4件であることを確認。
- エリア管理者は自町内会の通報者氏名が見え、他町内会の通報者は番地だけ。地域集計は全地域9／SOS5・道路2・建物1・その他1を維持。
- 位置不明・建物の登録住民・地域集計からの個別表示も公開条件を通す。地図は開始直後に東町内会のSOSだけ個別記号を表示し、非公開対象は地域の統計記号にする。通常通報の地図記号も赤・黄・旗を確認。
- 読取りレビューで見つかった自治体一覧の見出し、3分到達で入力画面まで閉じる問題、閲覧町内会の変更で元データが移る問題、救助訂正の欠落を修正。
- 3分境界の入力消失をブラウザーで再現してから修正。修正後は2分59秒で入力した文が3分11秒時点でも保持される。救助→履歴→訂正でSOSへ戻せること、閲覧町内会変更で統計が変わらないことも確認。
- 最終の読取りレビューでCritical／Importantの残件なし。新しい確認用タブでコンソールerror0件。
