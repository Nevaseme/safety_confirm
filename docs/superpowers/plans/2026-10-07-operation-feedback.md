# PlanD Mk1：操作結果を分かりやすくする実装計画

## 1. 目標・範囲

通信・保存・救助記録の操作で、「受け付けたか」「完了したか」「次に何をすればよいか」が分かるようにする。

- Androidと実験用PWAの既存画面を改善する。
- 対象は通信開始・停止、住居登録、無事／SOS、対応記録の新規保存・訂正、PWAの実験経路切替。
- Material 3を継続。通信JSONと保存形式、最小API 24は維持する。
- 自動接続、センサー、PLATEAU、DADSへの変更は今回に含めない。
- Android 2台での試験は待ち条件にしない。

## 2. 表示と動作

| 操作 | 押した直後 | 完了・現在の状態 | 失敗した場合 |
|---|---|---|---|
| 実験通信開始 | 接続しています… | サーバー接続済み・相手待ち／相手と接続中 | 接続できない理由・確認事項・再試行 |
| 情報保存 | 保存しています… | この端末に保存しました＋保存した内容・時刻 | 入力を残し、原因と再試行方法を表示 |
| 実験経路切替 | A ↔ Bへ切替中…など | サーバーが確定した経路を表示 | 最後に確認した経路と、切替できなかった理由を表示 |
| 共有停止 | 停止操作を受け付ける | 共有停止中 | 終了後の遅い応答で共有中に戻さない |

### 共通

- 操作したボタンの近くに結果を出す。画面上部だけの一時的な通知に頼らない。
- 処理中は対象ボタンと競合する操作を無効化し、二重保存・二重接続を防ぐ。通信の停止は接続中でも可能にする。
- 同じ操作の再試行成功時に、その操作の古いエラーを消す。別の未解決エラーは消さない。
- 色・回転表示だけでなく文字でも説明し、TalkBack／VoiceOverで状態変化を読み上げられるようにする。
- 保存中の画面再描画・受信更新で、入力内容や処理状態を上書きしない。

### 通信

- サーバーから参加確認を受け取るまで接続完了と表示しない。
- PWAは開始・停止・接続相手・現在の経路を同じ場所で操作・確認できるようにする。安否画面からも状態を確認できるようにする。
- Nearbyは既存の開始中・探索中・接続確認待ち・接続済み状態を使って表示を整理する。
- 実験通信の接続確定を15秒待っても応答がなければ停止し、再試行を案内する。
- 手動停止、画面を閉じたことによる停止、通信エラーを区別する。

### 保存と相手の受領

- Room／IndexedDBの保存完了をもって「この端末に保存しました」と表示する。
- 保存後の通信に失敗しても、保存失敗とは表示しない。「端末に保存済み。通信は再接続してください」と分ける。
- 受領確認件数は「今回の接続中に相手が保存を確認した件数」とする。個別の記録や救助担当者への到達を示す表示に流用しない。
- 保存が遅い場合も、確定前に成功・失敗と断定しない。保存中のまま二重実行を防ぐ。

### 経路切替

- Bだけが操作可能。Cは現在の経路を表示し、切替できないことを説明する。
- 現在選択中の経路と、切替処理中のボタンは無効化する。
- サーバーの経路確定通知で完了にする。送信しただけでは完了扱いにしない。
- 5秒応答がなければ「切替結果を確認できません」と表示して接続を終了し、再接続時に経路を取得する。
- Aが接続中でBCへ切り替えられない場合は「Androidの実験通信を停止してください」と表示する。

## 4. 完成条件

- 押した直後に反応があり、処理中・成功・失敗が操作箇所で分かる。
- 保存完了、相手待ち、相手の受領確認を混同しない。
- 経路切替はサーバーの確定結果と一致する。
- 連打しても対応記録の重複や接続のやり直しが発生しない。
- 失敗後も入力を保持し、再試行して復旧できる。
- 再接続・画面復帰後に古い状態やエラーを成功状態と混在させない。
- 既存のSOS→中継→対応結果共有の流れを維持する。
