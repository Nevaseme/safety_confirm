# 対応Webデモ1.6.1：操作改善

利用者の1.6.0への操作フィードバックを反映する。Androidとplan.txtは変更しない。

## 確認した原因と仕様

- 担当開始の通知は画面下に絶対配置され、解除ボタンと重なった。公開390×844で通知y708.7–752、解除ボタンy715–758を実測。詳細の通知は見出し内の専用行へ置き、操作ボタンを覆わない。
- 「未対応　北班」は状態と担当が連結されていた。状態「未対応」と「担当：北班」を別に表示し、担当者無しも維持する。
- 通報訂正には取り消しの入口がなかった。利用者が「履歴を残して取り消し、通常の一覧・地域集計から外す」を選択。取り消した通報はメニューから確認・復元できるようにする。本人のSOSは安否画面で扱い、道路等の通報と区別する。
- 地図には追加操作がなかった。利用者が「追加ボタン→地点をタップ」を選択。選択座標を通報に保存し、その地点に記号を置く。地点選択中は建物詳細を開かず、やめる操作と画面移動で選択を解除する。
- 比較用の1.5.4・1.5.5・1.6.0を残し、右側に「Web案1.6.1」を追加。旧1.6.0の動作は維持する。架空データ、再読込で初期化、Android画面未実装を明記する。

## ローカル検証結果

- 新規関数のexport不在で試験が失敗することを確認後に実装。案件モデル10件＋既存一覧4件の計14件成功。
- アプリ内ブラウザーで390×844とPC表示を確認。通知と解除ボタンの矩形の重なりはfalse。通知表示中に解除でき、担当者無しへ変わることを確認した。
- 道路閉塞の取り消しで総数9→8、道路2→1。メニューから取消理由と開始・解除・取り消しの履歴を表示でき、復元後に総数9へ戻ることを確認。
- 地図の追加→中央地点タップで入力画面へ進み、選択座標約130.81900／32.79040を保持。その通報記号のDOM座標属性が実際のクリック座標と一致することを確認。やめる操作と対応タブへの移動で地点選択が解除されることも確認。
- 新版では「未対応」と「担当：北班」が別要素。旧1.6.0では従来の「未対応　北班」を維持していることを確認。
- 最終コンソールerror0件。別の読取りレビューでもImportant/Criticalの残件なし。
- Android・実データ保存と同期は変更していない。
