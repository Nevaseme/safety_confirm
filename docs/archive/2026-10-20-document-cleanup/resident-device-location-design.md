# PlanD：住民・端末・建物と所在情報の設計

2026-10-20：この文書は旧案・検討経緯として保存する。現行仕様は[統合設計](../../superpowers/plans/2026-10-19-integrated-design.md)と[実装計画](../../superpowers/plans/2026-10-08-pland-roadmap.md)を参照。以下の旧方針を現行の実装指示として使用しない。

旧案の関連文書：[誰をどの建物で確認するかを決める設計](search-focused-design.md)。この関連文書も検討経緯であり、現行仕様ではない。

2026-10-10。設計案。アプリへの実装・位置検知の実証は未着手。

## 1. 目的

家に登録された住民について、誰が無事と回答し、誰が助けを求め、誰の確認が必要かを把握する。端末の位置・近距離検知・登録寝室を確認や捜索の手掛かりとして重ねる。

屋外でスマホを検知しただけでは本人を「無事」にしない。端末の所持者、観測時刻、位置の誤差があり、屋外でも救助が必要な場合がある。本人の回答、第三者による本人の確認、端末の観測を別々に残す。

## 2. 関連付け

| 対象 | 管理する内容 |
|---|---|
| 確認先 | 「山田さん宅」など訪問・確認のまとまり。複数建物を関連付けられる。範囲は任意で、土地の所有境界とは扱わない |
| 建物 | 建物ID、形状、任意の呼び名、外部データとの対応、確認した範囲と未確認事項 |
| 住戸・世帯 | 集合住宅の住戸や同居する人のまとまり。1建物に複数世帯があっても混同しない |
| 住民 | 人のID、名前、確認先・住戸との関係、普段使う建物・寝室。建物未指定も許容する |
| 端末 | 端末IDと利用者との関連付け。変更・共有・紛失を扱える履歴を持つ |
| 観測・確認記録 | 対象者または対象端末、災害、情報源、取得時刻、受信時刻、測定値、訂正履歴 |

基本の関連は「端末 → 登録された利用者 → 登録住居」。端末を直接建物に固定し、そこに人がいると推定しない。普段の登録先と、その災害で確認された所在は別にする。

端末を持たない子供や高齢者も住民として登録できる。同じ人に複数端末があっても人数は1人。共有端末の位置だけでは、登録された全員の位置を決めない。来訪者は住民とは別枠で確認先に関連付けられる。

## 3. 人について並べて表示する情報

| 情報 | 表示例 | 更新元 |
|---|---|---|
| 本人の回答 | 無事／SOS／回答なし | 本人の操作 |
| 人への確認・対応 | 本人を確認／救助完了／再確認が必要 | 対象者を明示した第三者の記録 |
| 本人の所在 | 避難所にいるとの回答／玄関前で本人を確認 | 本人または第三者の明示的な記録 |
| 端末の手掛かり | 端末位置 10:24取得・精度約15m／近くで端末を検知 | 測位・直接通信・将来のセンサー観測 |
| 平時の手掛かり | 登録寝室：建物1・2階東側 | 住居登録 |

第三者の確認は本人の回答欄を書き換えず、記録者と確認時刻を表示する。救助後も元のSOSは履歴に残し、未対応SOSと対応済みを区別する。新しいSOSや再確認記録があれば以前の完了表示で隠さない。

「応答なし」は安否確認要求を受け取って期限を過ぎた記録がある場合だけ使う。端末なし、要求未達、通信断、位置不明とは区別する。

## 4. 5人の家での表示例

| 住民 | 安否・対応 | 所在の手掛かり |
|---|---|---|
| 山田太郎 | 安否未確認 | 端末位置は建物の外側・10:24取得 |
| 山田花子 | 無事・本人回答 | 本人から「避難所にいる」と回答 |
| 山田一郎 | SOS・未対応 | 端末位置なし／登録寝室：建物1・2階東側 |
| 山田春子 | 安否未確認 | 位置情報なし |
| 山田健太 | 安否未確認 | 本人の端末登録なし |

家の集計は「登録住民5人／SOS1人・無事1人・安否未確認3人」。端末検知の人数を無事の人数に加えない。太郎がその災害について「無事」と回答すれば、無事2人・安否未確認2人へ変わる。

登録住民数は建物内にいる人数ではない。未登録の人がいる可能性も残るため、5人全員への確認が済んでも建物の確認完了を自動設定しない。集計は人ID単位で重複排除し、対応済みSOS、第三者による無事確認、食い違う記録がある場合は内訳を示す。

## 5. 位置情報の扱い

- 安否送信時に端末位置を取得する。取得を待ってSOS送信を止めず、まずSOSを保存・送信し、取得できた位置を関連付けて追加共有する。
- 各位置には対象端末、関連する安否記録、取得時刻、取得方法、精度、作成元を残す。再送・中継で取得時刻を新しくしない。位置のない既存データを住居座標で補わない。
- 新規取得と過去の測位結果を区別する。「SOS送信時の端末位置」は実際にその時点の測位が得られた場合だけ使い、以前の位置は「最後の端末位置」と取得時刻を表示する。
- 位置の誤差範囲が建物と重なる場合は内外を決めない。重ならなくても「建物外の位置情報」という手掛かりであり、人が屋外で無事と確認されたことにはしない。精度不足・古い測位・建物形状の欠損は判定保留にする。
- 精度半径は推定値で、確実にその円内にいるという境界ではない。建物の階や部屋を通常の平面座標だけで自動指定しない。
- Nearbyで直接検知した場合も、得られたのはその端末との近接通信の記録。検知した側が屋外でも、相手端末が屋外とは限らない。
- 中継された情報の受信は、元の端末を近くで検知したこととは別。最後の中継端末の位置を元の利用者の位置にしない。
- 通信の強さだけで方向・距離・部屋を確定しない。将来の音響等の観測も別の証拠として追加する。
- 新しい位置だけでSOS、無事、救助完了を変更しない。複数端末や時計の食い違いがある場合は、根拠を残して競合を表示する。

最初は安否操作時の取得と、表示中の手動「位置を更新」を対象にする。画面消灯中の常時測位、検知だけによる自動安否判定はこの設計の最初の実装に含めない。

## 6. 画面構成

メインは「地図」「安否登録」。住居・住民・端末の関連付け、共有設定はハンバーガーメニューにまとめる。

### 地図

- 家のまとまりは薄い青の範囲と「山田さん宅」。選択前は住民の安否を短く集計表示する。
- 建物は形状と番号・任意の名前で示す。住民のSOSで建物全体を赤く塗らない。建物の被害・確認状況は独立した表示とする。
- 測位で得た位置はスマホ形の記号、本人が確認された所在は人形の記号を使う。SOSなら赤いラベルを添える。凡例は短い「端末位置」「本人の確認位置」とする。
- 位置不明の人は家の詳細に表示し、家の中央を測位点のように描かない。登録寝室を表示するときは「登録寝室」の表記を残す。
- 住居と離れた端末も地図上に表示し、住民を選ぶと登録先と観測位置の関係を確認できる。全員分の線や精度円は常時描かず、選択中の対象だけに表示する。
- 端末が複数あっても住民集計は1人。重なるマーカーは展開でき、SOSを安全な人の集約表示で隠さない。

### 家を選んだ下部パネル

1. 山田さん宅／登録住民5人。
2. SOS1人・無事1人・安否未確認3人。
3. 住民一覧。左に名前と安否、下に「端末位置」「本人回答」「登録寝室」など根拠を短く表示。
4. 建物の確認状況。建物1：1階確認済み・2階未確認、建物2：未着手など。

一覧は未対応SOS、確認が必要な人、確認済みの人を見分けられる配置にする。「端末が外にある」だけで確認対象から除外しない。詳細を開くと時刻・精度・情報源・履歴・本人への確認記録を表示する。

### 安否登録

災害・訓練を明示して「無事」「SOS」を大きく表示。保存直後に「SOSを保存」、位置取得後に「端末位置を追加」、受領確認後に「相手端末に届きました」と段階を分ける。共有されていないのに届いたと表示しない。位置を取得できなくても安否の保存・共有は続ける。

注意書きを増やさず、情報源の短いラベルと配置で意味を伝える。本文は日本語のシステムフォント14〜16spを基準、左揃え。白 #FFFFFF、背景 #F3F7FA、濃紺 #163C54、青 #155EEF、SOS赤 #B42318、確認された無事の緑 #18794E を継続する。色だけで状態を伝えない。

## 7. 次の実装順序

1. 住民IDと端末IDを分離する保存・通信形式を設計し、既存利用者・住居・安否の移行を用意する。最初の操作は1端末1利用者のまま、端末なし住民の登録と第三者確認を扱えるようにする。
2. 安否送信時の測位、取得失敗、時刻・精度の保存と共有を追加する。従来端末との互換性を版管理する。
3. 5人の一覧、家の範囲、建物、端末位置を同じ画面にまとめる。今回の表の状態を固定データで比較・確認してから実データへ接続する。
4. 屋外端末、室内外を判定できない誤差、古い位置、複数端末、端末なし、SOS後の屋外移動、記録の競合を模擬試験する。
5. Android1台とPWAで測位・保存・中継を確認する。PWAは表示中の取得を対象にする。実際のNearby検知・屋内外の推定精度はAndroid追加後に評価する。

PLATEAUの建物形状・属性は建物に関連付ける。世帯・住民・端末・現在の所在はPlanDの記録として保持し、PLATEAUから人の居場所を推定しない。高度なセンサーによる捜索は既存の第8段階へ接続する。

## 8. 確認基準

- 5人中1人の端末が建物外に移動しても無事の人数が自動で増えず、残り4人を在宅としない。
- SOSの人の端末が外に移動してもSOSと確認対象を保持する。
- 無事の回答、第三者による本人確認、端末の検知を見分けられる。
- 位置なしでもSOSを保存・共有でき、位置の追加でSOSが重複しない。
- 居住先が同じでも端末位置と登録寝室が混同されない。
- 中継後も元の取得時刻・端末・精度が保持され、古い位置が新しい位置を上書きしない。
- 端末なし住民、複数端末の住民、未登録来訪者を混同せず人数を表示する。
- 全住民の無事確認だけで建物の確認状況を完了にしない。

根拠：Androidの位置情報は取得時刻と推定精度を保持する。[Android Location](https://developer.android.com/reference/android/location/Location)。Nearby Connectionsは近距離端末の探索・接続・データ交換の仕組み。[Google Nearby Connections](https://developers.google.com/nearby/connections/overview)。上記の安否判定・画面構成は、これらの測定・通信情報を扱うPlanDの設計判断。
