# PWA・Windowsの実験手順

対象は実装済みのPWA 1.4.0とAndroid 1.4.5。今後の仕様は[設計書](../docs/superpowers/plans/2026-10-19-integrated-design.md)、確認範囲は[実装・試験状況](../docs/STATUS.md)を参照。

Android本体、iPhoneのPWA、Windowsブラウザーを使います。架空の情報だけで実験してください。
これはNearbyの無線試験ではありません。PCを経由した、同期・保存・中継・対応記録の実験です。

## 建物・住戸と建物の対応記録

1. 「建物」から建物名・緯度・経度を登録します。初期位置は自分の登録住居です。同じ建物が既にある場合は、その建物を選んでください。
2. 建物の詳細で住戸（例：201号室・戸建て）を追加し、「自分の住居に設定」します。各端末の住民が同じ建物・住戸を選ぶと、複数人が関連付けられます。住戸未指定も可能です。
3. 建物・住戸名の訂正は登録者が行います。同じIDを保つため、住民の関連付けは残ります。関連付けの変更・解除は自分の分だけ行います。
4. 開始中の災害を選び、建物の確認中・要対応・対応完了の記録・再確認を保存します。「確認した範囲」「未確認事項」は必須です。未確認事項がない場合も「なし」と明記します。
5. 自分の対応記録を選んで訂正・撤回できます。他の担当者の記録は残ります。個人の救助完了から建物全体を完了扱いにはしません。
6. Androidの地図では四角が建物、丸が住民です。建物の対応状況・範囲・未確認事項と、関連する住民・住戸・寝室を詳細で確認します。

建物と住居の関連付けは平時の登録です。現在位置・在宅の確認や、過去の災害時にそこに住んでいた証明ではありません。対応記録だけを災害ごとに分けます。

建物情報を共有する実験では、全端末を1.4.0以降に更新してください。旧版では建物・住戸・建物対応を表示できません。PWA下部が「PlanD 1.4.0」になっていることを確認します。

## 災害・訓練ごとの安否確認（現行版）

- 自分の登録を済ませ、「安否」の「地震発生」から名称・対象地域・訓練かどうかを指定して開始します。1人の操作で開始でき、共有中の同じグループへ開始情報を送ります。
- 開始した災害について「無事」「SOS」と個人の対応記録を保存します。別の災害には過去の安否・救助完了を持ち越しません。
- 受信側に選択済みの災害がなく、開始中の災害が1件なら、その災害を選択して保持します。別の災害が届いても自動で切り替えません。複数の候補は上部の選択欄から選びます。
- 開始した人が終了できます。終了した災害と「過去の情報（災害未分類）」は閲覧のみです。終了情報をまだ受信していなかった端末の記録は、後から届いても履歴として保持します。
- 現行版は手動開始です。対象地域は名称として保存します。今後の速報受信・人数条件・応答なしの表示規則は設計書に従って追加します。
- 災害ごとの共有は参加端末をすべて1.3.0以降に更新して試します。旧版は災害ごとの安否・対応記録を解釈できません。旧版との通信で交換する住民・旧記録を今回の安否として扱わないでください。

## 操作結果の表示

- 接続しています → サーバー接続済み・相手待ち → 相手と接続中、の順で状態を表示します。接続完了の確認には最大15秒待ちます。
- 「登録・接続」で通信開始と停止を操作できます。経路切替はサーバーの応答で確定し、拒否理由をその場に表示します。
- 保存中は二重操作を防ぎ、結果を保存ボタンの近くに表示します。保存完了と相手の受領確認は別の表示です。
- 失敗した入力は残ります。修正して再試行してください。グループ変更時は前のグループの保存メッセージを消します。
- PWA更新時：サーバー起動中にページを開き、その後同じアドレスの実験ページをすべて閉じて再度開いてください。下部が「PlanD 1.4.0」になっていることを確認します。ブラウザーのデータ削除は不要です。
- [操作結果・保存・中継の確認範囲](../docs/STATUS.md)

## 起動

Node.js 24以上を使用します。最初だけ `npm ci` を実行してください。

1. 初回のみ `node scripts/setup.mjs`。OpenSSLは `C:/Program Files/Git/usr/bin/openssl.exe` を使用します。別の場所にある場合は実行前に `$env:OPENSSL = "OpenSSLの実行ファイルのパス"` を指定します。既存の証明書は上書きしません。
2. `npm start` でHTTPS/WSSサーバーを起動します。
3. 必要な間だけ別のターミナルで `node cert-server.mjs` を起動します。公開CA証明書以外は配布しません。
4. `.local/connection.txt` に端末用URL、接続コード、証明書の指紋が保存されます。Wi-Fiのアドレスを選び、仮想ネットワークのアドレスは使わないでください。

ポートはHTTPS/WSSが8443、証明書ダウンロードだけ8080。サーバーは住民情報を保存せず、受領確認も生成しません。
PCのネットワークが変わり証明書のIPと一致しなくなったら、検証を止め、証明書とAndroid debug版の公開CAを揃えて再設定してください。証明書チェックを無効化しないでください。

## 証明書の設定

接続を暗号化するため、この実験専用のCAを使います。CAを信頼する設定は、利用者の確認を得てから行います。
`.local/ca.key` と `server.key` は秘密鍵です。PWAの公開ファイル、配布ZIP、ソース管理へ入れないでください。

- Windows：現在のユーザーの「信頼されたルート証明機関」に `.local/PlanD-Lab-CA.cer` を登録。
- iPhone：Safariで `http://PCのWi-Fiアドレス:8080/PlanD-Lab-CA.cer` を開き、設定 → 一般 → VPNとデバイス管理でインストール。設定 → 一般 → 情報 → 証明書信頼設定で **PlanD Local Experiment CA** を信頼。
- Android：今回のdebug APKは実験CAの公開証明書をアプリ内に含めます。OS全体のCA信頼設定を変更する必要はありません。release版にはこのCAを含めません。
- Windowsの受信が遮断される場合：許可を得たうえで `scripts/enable-firewall.ps1` を管理者として実行。PrivateネットワークのLocalSubnetからTCP 8080/8443だけを許可します。

証明書名・指紋を確認してください。接続コードは実験ごとの入室用で、住民・救助者本人の認証ではありません。

## iPhoneとWindows

1. 証明書を設定した後、HTTPSのURLをSafariで開きます。
2. iPhoneは共有メニュー → ホーム画面に追加。以降はそのアイコンから開きます。
3. Safariとホーム画面版で保存領域が引き継がれるとは仮定しません。追加後の画面で登録内容を確認し、なければ登録し直してください。
4. iPhoneは役割B、Windowsは `?profile=C` のURLで役割Cにします。別々の端末ID・保存領域です。
5. グループ `lab-1007`、表示名 `佐藤 花子` / `鈴木 一郎（確認担当）`、架空の住居を登録し保存。
6. 接続コードを入力して「実験通信を開始」。画面を閉じると停止するため、復帰後は手動で開始してください。

ブラウザーのデータ削除や保存容量の制約で情報が消えることがあります。PWAは実験端末であり、実地利用向けの恒久保存を保証するものではありません。

## Android

1. 更新APKを既存アプリへ上書きインストール。アンインストールは不要です。
2. 設定で `lab-1007` / `山田 太郎` と架空の住居を保存します。旧グループの情報は残ります。
3. 設定の「iPhone・PCとの通信実験」にWSSアドレスと接続コードを入力。
4. 「実験通信を開始」。役割Aになります。Nearbyとは同時に開始しません。
5. Androidの実験通信も画面表示中だけです。既存のNearbyの背景通信とは条件が異なります。

## 試験手順

### A → B → C の中継

1. Windows Cも登録・接続。初期経路はABなので、CにはAの情報が届かないことを確認。
2. Android AとiPhone Bを接続。Aで「地震発生」から訓練を開始し、SOSを保存。Bで同じ災害を選び、一覧でA・SOS・部屋を確認。
3. Aの「実験通信を停止」を押す。
4. Bを一度閉じ、再び開く。Aの情報が残っていることを確認。
5. Bを接続し「B ↔ C の実験」を押す。Aが接続したままでは切り替えを拒否します。
6. Cで同じ災害のAのSOSと部屋が表示されれば、Bに保存した開始情報と回答からの中継が成立。

### 救助・確認結果と訂正

1. Cの「住民・対応」からAを選び「本人の救助完了」を記録。
2. Bで対応記録を受信し、記録者・時刻・対象者を確認。
3. Cで自分の記録を選び、理由を書いて「要救助」へ訂正。訂正前の記録も履歴に残ることを確認。
4. Bから経路ABに戻す。Aを再接続し、対応履歴がAndroidの地図・一覧・詳細にも届くことを確認。
5. A本人のSOSは第三者の記録では変わらないこと、建物全体の救助完了にならないことを確認。

複数の記録者による記録は併記します。端末時計で勝手に一方を採用しません。訂正できるのは画面上では自分の記録だけです。暗号署名による作成者認証は未実装です。
今回の試験には全端末で1.3.0以降を使います。旧版への災害情報の変換は行いません。

### 次の災害と履歴

1. 開始者が安否確認を終了し、回答・対応記録が閲覧のみになることを確認。
2. 新しい訓練を開始。前回の「無事」「SOS」「本人の救助完了」が今回に表示されないことを確認。
3. 上部から前の訓練と「過去の情報（災害未分類）」を選び、記録が残っていることを確認。
4. 再起動しても表示対象が保持され、別の開始・終了情報を受信しても表示対象が勝手に変わらないことを確認。

### 建物の登録・対応と中継

1. Android Aが建物と住戸を登録し、自分を関連付けます。iPhone Bで受信した同じ建物・住戸を選び、登録住民が2人になることを確認。
2. Aが住戸名を訂正。Bの自分の住居表示にも訂正が反映され、住民数が変わらないことを確認。
3. 開始中の災害で、Bが建物へ「対応完了の記録」、範囲「1階共用部」、未確認事項「2階」を保存。個人のSOSが残り、建物全体の安全確認済みとは表示されないことを確認。
4. Aを停止してB→Cへ切り替え。Cで建物・住戸・住民の関連付けと、対応範囲・未確認事項・記録者を確認。
5. Bが自分の記録を「再確認が必要」に訂正。訂正前の履歴も残り、再接続したAへ届くことを確認。
6. 別の訓練を開始すると建物・住戸の登録は残り、前回の建物対応は今回に表示されないことを確認。

### 再送・切断・ネットなし

- 相手を切断した状態で更新し、再接続後に最新状態が届くことを確認。
- 接続し直しても重複レコードや古い状態への逆戻りがないことを確認。
- 初回のPWAキャッシュ完了後、必要に応じて利用者の操作でWANを切断。同じWi-Fi内のPC・Android・iPhoneで交換する。PC全体のネット切断は、この作業用チャットも切れる可能性があるため、手順を確認してから実施する。
- iPhoneを閉じた状態の受信は完成条件にしない。復帰・再接続後の回復を確認する。

## 検証と通信仕様

Androidエミュレーターとの自動試験は[専用手順](../android/LAB_AUTOMATED_TESTING.md)を参照。必要引数、保存後に返信する相手役、スキップの確認方法をまとめています。

`npm test`：IndexedDBと同期、保存失敗、トランザクション中断、訂正、ルーターの経路制約、共通JSONを検証。

- 住民登録と旧安否はversion 1のSUMMARY / REQUEST / RECORD / ACK。
- 旧救助記録はversion 2のCARE_SUMMARY / CARE_REQUEST / CARE_RECORD / CARE_ACK。
- 災害記録はversion 3のINCIDENT_SUMMARY / INCIDENT_REQUEST / INCIDENT_RECORD / INCIDENT_ACK。START・END・ANSWER・CAREを不変のeventIdで保存し、incidentIdで分けます。作成者ごと・災害ごとのsequenceで回答の新旧を比較し、端末時計による逆戻りを防ぎます。
- 建物記録はversion 4のPLACE_SUMMARY / PLACE_REQUEST / PLACE_RECORD / PLACE_ACK。BUILDING・UNIT・HOME・CAREを保存。建物記録のsequenceはグループ内・作成者ごとに増やします。対応の訂正は同じ災害・建物・作成者の古い更新番号へだけ適用し、不正な循環で表示が消えないようにします。
- 救助記録は不変のeventId、対象subjectId、authorId/name、時刻、action、note、任意のsupersedes。
- 個人の救助記録の範囲は個人です。建物対応は独立したv4の記録で、個人記録からは導出しません。
- JSON上限24,000 UTF-8 bytes、一覧は100件ずつ、更新番号・時刻はJavaScriptで正確に表せる整数まで。
- 同じeventIdで内容が異なる記録は保存・ACKせずエラー表示。訂正は新しいeventIdで追加。
- 保存失敗時はACKしません。再接続時の一覧交換で再送します。
- AndroidのRoom schema 1→2でcare_events、2→3でincident_events、3→4でplace_eventsを追加。旧情報は保持します。PWAはIndexedDB 1→2でincidents、2→3でplacesを追加し、既存の住民・旧記録・設定を保持します。

## 実験終了後

1. 全端末の実験通信を停止し、サーバーを終了。
2. iPhone：VPNとデバイス管理から **PlanD Local Experiment CA** を削除。
3. Windows：`scripts/cleanup-trust.ps1` で今回の証明書だけを現在ユーザーから削除。ファイアウォール規則の削除は管理者が必要です。
4. 継続して実験する場合は設定を残す選択も可能です。残した設定は試験結果に記録します。
